# Сортировка писем ДМС — рабочий процесс репозитория

## Когда применять

Любая задача в этом репозитории: понять, как работает сканер, запустить проверку или боевой прогон, изменить правила отбора, обновить документацию, разобрать ошибку, подготовить и опубликовать изменения.

## Карта репозитория

| Путь | Назначение |
|---|---|
| `scan_flag.js` | сканер: IMAP, разбор писем и вложений, проверка адресов и полисов, звёздочки, перемещение |
| `sergiev_posad_settlements.json` | справочник 293 населённых пунктов Сергиево-Посадского округа |
| `tools/` | разовые диагностические скрипты (ящик, вложения, аудит UID); конфиг читают из родительской папки |
| `docs/README-ops.md` | эксплуатационная памятка: пути, логи, запуск |
| `.claude/skills/vega-dms-mail/` | этот скилл |

**Не в репозитории:** `config.json` (пароль ящика), `scan_state.json`, `last_scan.json`, журналы, `archive/`, `node_modules/`, docx.

## Что делает сканер

- Раз в 15 минут просматривает INBOX ящика `vegam2020@rambler.ru`.
- Берёт только «списочные» письма: тема или вложение содержат списки, прикрепление, открепление, застрахован, ДМС, snyat.
- Пароли к ZIP берёт из соседних писем и рассылок (папка «ЗЕТТА»).
- Ищет адреса по 293 населённым пунктам и индексу 1413xx; одноимённые посёлки в других регионах отсекает.
- Если адресов в списке нет — проверяет номера полисов по базе (`risk_list`).
- Маршруты отправителей: «НЕЗАВИСИМАЯ ЛАБОРАТОРИЯ ИНВИТРО» → «ИНВИТРО», INVITRO LAB и «Лаборатория СИТИЛАБ» → Корзина.
- Гарантийные письма («СРОЧНО…», `ГП*.zip`) не трогает.
- Состояние ведёт по UID, повторно письмо не проверяет; `RESCAN=1` — полная перепроверка.

## Запуск

```powershell
npm install
node scan_flag.js                    # боевой прогон
$env:DRY_RUN="1"; node scan_flag.js  # проверка: без флагов, перемещений и записи состояния
$env:RESCAN="1"; node scan_flag.js   # перепроверить всё заново
Remove-Item Env:DRY_RUN
```

Переменные: `IMAP_HOST`, `IMAP_PORT`, `IMAP_USER`, `IMAP_PASS`, `IMAP_LIMIT`, `DRY_RUN`, `RESCAN`.

Конфиг `config.json` лежит рядом со скриптом и содержит пароль. Не выводить его в чат, не копировать, не коммитить.

Продакшен:

- задача **«Vega DMS Mail Scan»** каждые 15 минут (S4U) через `C:\ProgramData\VegaDMS\scan.cmd`;
- `Get-ScheduledTaskInfo -TaskName 'Vega DMS Mail Scan'` — `LastTaskResult` должен быть 0;
- логи `scan.log` и `scheduler.log`, отчёт `last_scan.json` (содержит ПДн — не публиковать).

## Внесение изменений

- Сохранять контракт `DRY_RUN`: в этом режиме никаких флагов, перемещений и записи состояния.
- Любое перемещение или флаг ставить только под проверкой `if (!DRY_RUN)`.
- Маршрутизация по отправителю имеет приоритет над логикой списков.
- Если база недоступна, проверка полисов должна возвращать «не определить» и оставлять письмо в INBOX — не переносить по ошибке.
- Новые страховщики и посёлки: править `ORGIDS`, `INSURER_RE` и `sergiev_posad_settlements.json`; список страховщиков держать в согласии с `~/.claude/tools/lists/mappings.js`.
- Диагностические скрипты в `tools/` читают `config.json` из `..` — сохранять это при переносе файлов.
- Проверять изменения на ограниченной выборке: `$env:IMAP_LIMIT="50"`.

## Проверка ошибок

- `DRY_RUN=1 node scan_flag.js`: `checked / flagged / moved / routed`, `errors=0`;
- `last_scan.json`: массивы `errors` и `warnings` пусты;
- `tail scan.log` — свежие строки без исключений;
- после прогона не должно оставаться `scan.lock` (снимается при выходе);
- задача: `LastTaskResult: 0`, `NextRunTime` заполнен.

## Подготовка к публикации

1. `git status` — только код и документация.
2. `.gitignore` исключает `config.json`, `scan_state.json`, `last_scan.json`, `*.log`, `scan.lock`, `archive/`, `node_modules/`, `docs/*.docx`.
3. Перед коммитом убедиться, что секреты не попали в индекс: `git diff --cached --name-only | grep -E "config|state|log"` не должен ничего найти.
4. Коммит с понятным сообщением на русском и строкой `Co-Authored-By: Claude Code <noreply@anthropic.com>`.
5. `git push origin main`.
6. Проверить приватность: `gh repo view atregubov87-svg/vega-dms-mail --json visibility`.

**Никогда не коммитить:** пароль ящика, состояние обработки, журналы, отчёты с персональными данными пациентов.
